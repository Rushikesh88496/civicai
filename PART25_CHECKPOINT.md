# Part 25 Checkpoint Report - Citizen AI Assistant with RAG

## Status: READY - YES

## What Was Implemented

**RAG backend (`app/rag/`, `app/services/assistant_service.py`,
`app/api/v1/assistant.py`, `app/schemas/assistant.py`)** - a citizen-facing Q&A
assistant grounded in retrieved policy documents and the citizen's *own*
complaint data, powered by Groq + pgvector:

- `app/rag/embeddings.py` - `EmbeddingService` (OpenAI-compatible embeddings
  client) plus `KeywordEmbedder` used as a deterministic, offline fallback for
  tests and for seeding the KB without a live embedding provider.
- `app/rag/knowledge_base.py` - `KnowledgeBase` with `add_document` /
  `search` / `doc_count` and `ensure_knowledge_base(db)` (idempotent by slug).
  34 seed documents across Municipal Charter / Citizen FAQ / Complaint SOP /
  Water & Drainage policy / Grievance Redressal / Departments & routing /
  priority definition.
- `app/rag/retriever.py` - `RetrieverService`: pgvector (cosine) similarity with
  `<= :k` filter semantics over the `knowledge_base_documents.embedding` vector
  column; returns docs as `RetrievedDoc` (title, slug, reference, relevance);
  zero-vector guard so hallucination paths stay well-formed.
- `app/services/assistant_service.py` - the policy engine executing
  `Question -> Permission check -> Retrieve -> Build context -> Groq -> Validate
  -> Return`, plus a streaming variant (`stream_response` yielding
  `meta / delta / sources / done` SSE events). DB lookups (own complaints,
  why-P1 history, ward hotspots, department routing, infrastructure summaries,
  work-order data, current ward) are all scoped to the authenticated user; every
  answer carries a disclaimer, `ai_prediction` tag and `generated_by`.
- Hallucination safety: when the citizen asks something outside the data,
  a template answer is returned (generated by "synthesized"), never fabricated
  specific facts.
- **API (`app/api/v1/assistant.py`)** - prefix `/api/v1/assistant`, CITIZEN-only
  (401 anonymous, 403 other roles):
  - `POST /ask` - single answer; 503 if `GROQ_API_KEY` unconfigured and LLM needed.
  - `POST /ask/stream` - SSE via `text/event-stream` (meta / delta / sources / done).
  - `GET /conversation` / `DELETE /conversation` - this citizen's saved history.
  - The AI service is injected via a request-scoped dependency
    (`_ai_for_request`) because `get_ai_service(settings=...)` would otherwise
    be bound by FastAPI as a second (embedded) body parameter - found while
    writing tests (every `/ask` returned 422 before the fix).
- **Models + migration** - three new tables (migration
  `alembic/versions/c1d2e3f4a5b6_citizen_ai_assistant_knowledge_base.py`
  **applied; head = `c1d2e3f4a5b6`**, chained from Part 24 head `b1c2d3e4f5a6`):
  - `assistant_conversations` - per-citizen conversation (user FK, `is_active`).
  - `assistant_messages` - `role` / `content` / `sources` JSONB with a
    **server default** `'[]'::jsonb` (originally omitted - NOT NULL violation
    caught by the test suite, then fixed in-migration and back-patched on the
    dev DB via `ALTER TABLE ... SET DEFAULT`) / `generated_by` / FKs.
  - `knowledge_base_documents` - slug, title, reference, body and a pgvector
    `embedding` column (hnsw enabled).

## Known Limitations / Notes

- The live KB uses the offline **`KeywordEmbedder`** (deterministic, per-keyword
  bit vectors) so the demo runs without a separate embeddings API key; quality of
  retrieval can be improved by swapping in a real embedding model (the service
  interface is the seam). Groq powers the answer generation.
- `alembic check` noise is pre-existing and unrelated to Part 25 (see above);
  only `alembic current` = head is used as the migration gate.
- Conversation memory is capped (`_HISTORY_TURNS`) and only the citizen's own
  messages are ever included; the widget refreshes history when opened.
- The `DELETE /conversation` response returns `{cleared, messages_deleted}`
  (no human `message` string) - frontend treats it purely as a success signal.
- `KnowledgeBase` requires existing vector rows for cosine ranking; documents
  with a non-meaningful (zero) embedding are skipped by the retriever guard so
  the pipeline degrades to a synthesized answer instead of erroring.
